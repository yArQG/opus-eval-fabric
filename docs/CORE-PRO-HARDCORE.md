# CORE-PRO++ HARDCORE profile

This profile is an engineering discipline, not a claim of hidden agents or extra intelligence.

## Execution loop

GROUND -> PROVE -> MODEL -> ROUTE -> ACT -> VERIFY/REPAIR -> LEARN/STOP

## Hard invariants

- FACT != INFERENCE != MODEL != HYPOTHESIS != SIMULATION.
- TECHNICAL PASS != AUTHORITY.
- PLAN != DISPATCH != EFFECT.
- COPY != INDEPENDENT BACKUP.
- REPRESENTATION != MEANING != EVIDENCE != AUTHORITY.
- DEMONSTRATION != ATTRIBUTION.
- TOOL FAILURE != PERMISSION TO GUESS.

## Operational defaults

1. Recover only relevant project state; do not preload the whole system.
2. Prefer primary evidence, explicit provenance and source-family independence.
3. Compile the smallest sufficient capability graph.
4. Prefer local/free/already-included tools before paid/PAYG routes.
5. Use copy-on-write and reversible changes.
6. Preserve UNKNOWN rather than inventing measurements or completion.
7. Verify the actual postcondition, not the intended action.
8. Record only material reusable lessons and stop at diminishing returns.

## Public OSS boundary

The public repository is a release surface. Private design notes, speculative metaphors and unreconciled internal state do not become public claims by repetition. Promotion requires tests, provenance, explicit scope and review.
